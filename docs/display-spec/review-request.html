1. 画面デザイン

レビュー依頼登録画面のモックアップを開く

GitHub上のOrganizationまたはユーザー、リポジトリ、Pull Requestを選択し、レビューエージェントへレビューを依頼する。本書の対象範囲はレビュー依頼登録画面、および同画面に表示される共通シェルとする。

関連画面：SCR-01 コードレビュー一覧・SCR-04 GitHub連携設定・SCR-03 レビュー結果確認

確認方法モックアップはブラウザで直接開ける。GitHub Personal Access Tokenが未設定の場合は入力領域が表示されないため、画面上部またはサイドバーの「設定」からダミートークンを保存して確認する。

領域構成内容区分
アプリケーションヘッダーブランド、言語切替、設定導線共通シェル
サイドバーコードレビュー一覧、レビュー依頼登録、設定、開閉操作共通シェル

1.2 操作フロー

  1. Organization / ユーザー選択
  2. リポジトリ選択
  3. PR選択
  4. 内容確認・送信
  5. 一覧へ遷移

進捗表示は画面上では「Organization / リポジトリを選択」「PRを選択」「内容を確認して送信」の3ステップとする。Organization / ユーザーのみを選択した状態は第1ステップに含める。

ID状態表示内容進捗

CM-03ヘッダー設定リンク設定アイコンを表示する。GitHub連携設定

2.2 画面固有項目

ID項目名種別必須表示・入力内容データソース
RR-01画面タイトル表示—「レビュー依頼登録」固定文言
RR-02画面説明表示—依頼に必要な3項目、およびClosed状態のPRを選択できない旨を表示する。固定文言
RR-03進捗表示表示—3ステップの現在位置と完了済みステップを表示する。画面内の選択状態
RR-04Organization / ユーザー選択必須認証利用者が参照可能なOrganizationおよびユーザーアカウントから1件を選択する。未選択値は「選択してください」とする。GitHub連携API
RR-05リポジトリ選択必須RR-04で選択した所有者に属し、認証利用者が参照可能なリポジトリから1件を選択する。GitHub連携API
RR-06PR一覧見出し表示—「プルリクエストを選択」固定文言
RR-07PR選択カード選択必須PR番号、タイトル、ブランチ、作成者、PR状態を表示し、1件を単一選択する。GitHub連携API
RR-08PRなしメッセージ表示—選択可能なPRが0件の場合、「レビューを依頼できるOpen状態のPRはありません。」と表示する。PR取得結果
RR-09送信内容見出し表示—「レビューエージェントへの送信内容」固定文言
RR-10送信内容表示—organization、repository、pull_requestの確定値を表示する。RR-04、RR-05、RR-07
RR-11レビュー依頼を送信ボタン—確定した3項目をレビューエージェントへ送信する。PR選択後に表示
RR-12キャンセルリンク—依頼を送信せずコードレビュー一覧へ戻る。PR選択後に表示
RR-13GitHub認証情報未設定通知表示—Personal Access Tokenが未設定であること、および設定が必要であることを表示する。GitHub連携設定状態
RR-14設定画面を開くリンク—GitHub連携設定を行う。GitHub連携設定
RR-15エラー通知表示—候補取得または送信に失敗した場合、原因と再操作の案内を表示する。各APIの処理結果

3. 入力項目・操作項目の振る舞い

3.1 入力チェック

ID対象チェック契機チェック内容エラー時の振る舞い
VL-01GitHub認証情報初期表示GitHubアクセスに必要な認証情報が設定済みであること。RR-13とRR-14を表示し、RR-03〜RR-12を表示しない。
VL-02Organization / ユーザーリポジトリ取得前、送信時候補一覧に存在し、かつ認証利用者が参照可能な値であること。リポジトリおよびPRの選択状態をクリアし、項目付近にエラーを表示する。
VL-03リポジトリPR取得前、送信時選択したOrganization / ユーザーに属し、かつ認証利用者が参照可能な値であること。PRの選択状態をクリアし、項目付近にエラーを表示する。
VL-04Pull Request一覧表示時、送信時選択したリポジトリに属し、状態がOpenであること。Closed状態は候補から除外する。送信を中止し、最新のPR一覧を再取得して、選択対象外になった旨を表示する。
VL-05送信内容全体送信時Organization / ユーザー、リポジトリ、PR番号の3項目がすべて確定していること。送信を実行せず、不足項目を示す。通常操作では3項目確定前に送信ボタンを表示しない。
VL-06重複依頼送信時同一リポジトリ・同一PR・同一最新コミットに対する処理中または有効なレビュー依頼が存在しないこと。新規依頼は作成せず、既存依頼が確認できるコードレビュー一覧またはレビュー結果への導線を表示する。

3.2 操作定義

ID操作前提条件処理処理後
OP-01Organization / ユーザーを選択GitHub認証情報が設定済み。配下の参照可能なリポジトリを取得する。変更前のリポジトリおよびPR選択は破棄する。成功時はリポジトリ選択を有効化する。失敗時はRR-15を表示し、再選択または再取得を可能にする。
OP-02リポジトリを選択Organization / ユーザーが選択済み。選択リポジトリのPRを取得し、Open状態のみを候補として表示する。変更前のPR選択は破棄する。候補があればST-04、なければRR-08を表示する。
OP-03PRカードを選択Open状態のPR候補が1件以上ある。選択中のPRを単一選択に更新し、選択カードを視覚的かつ支援技術上識別可能にする。ST-05へ移行し、送信内容と操作ボタンを表示する。
OP-04別のPRカードを選択PRが選択済み。既存選択を解除し、新しいPRに選択を変更する。送信内容のpull_requestを即時更新する。
OP-05レビュー依頼を送信VL-02〜VL-06を満たす。ボタンを無効化してST-06とし、Organization / ユーザー、リポジトリ名、PR番号をサーバーへ送信する。クライアント側とサーバー側の双方で二重送信を防止する。成功時はコードレビュー一覧へ遷移し、対象PRを含む受付完了通知を表示する。失敗時は入力値を維持してRR-15を表示し、再送信を可能にする。
OP-06キャンセルなし。レビュー依頼を作成しない。コードレビュー一覧へ遷移する。
OP-07設定画面を開くGitHub認証情報が未設定。入力中の依頼情報は存在しないため保存しない。GitHub連携設定へ遷移する。
OP-08言語を切り替えるなし。選択言語を利用者設定として保存する。現在URLを維持して画面を再表示する。未送信の選択状態は可能な限り維持する。
OP-09サイドバーを開閉するなし。サイドバーの幅とラベル表示を切り替える。開閉状態を利用者設定として保存し、次回表示時に復元する。

3.3 送信データ

レビューエージェントへ送信する業務データは次の3項目とする。画面表示用のPRタイトル、ブランチ、作成者は送信対象に含めない。

項目型必須内容
organization文字列必須OrganizationまたはユーザーのGitHubログイン名。
repository文字列必須リポジトリ名。所有者名を含めない。
pull_request正の整数必須対象リポジトリ内のPull Request番号。
 
organization: acme-corp
repository: web-frontend
pull_request: 482

4. 画面状態と例外処理

事象利用者への表示復旧操作入力状態
GitHub認証情報が未設定設定が必要である旨をエラー通知として表示する。GitHub連携設定へ遷移する。選択領域を表示しない。
認証情報が無効または期限切れGitHubへの認証に失敗した旨を表示する。認証情報そのものは表示しない。GitHub連携設定へ遷移する。既存候補を破棄する。
候補取得に失敗取得対象と再試行可能である旨を表示する。再取得または上位項目の再選択。確定済みの上位選択は維持する。
選択可能なOpen PRが0件RR-08を表示する。別のリポジトリを選択する。Organization / ユーザーとリポジトリは維持する。
選択後にPRがClosedへ変更現在の状態では依頼できない旨を表示する。PR一覧を更新し、別のPRを選択する。PR選択のみ解除する。
同一対象の依頼が存在重複依頼を作成しない旨と既存依頼への導線を表示する。既存依頼を開く、または別のPRを選択する。選択値は維持する。
送信処理に失敗依頼を登録できなかった旨と再試行案内を表示する。再送信またはキャンセル。3項目の選択値を維持する。
セキュリティ要件候補取得と送信の可否は画面上の活性制御だけに依存せず、サーバー側で認証、参照権限、所有関係、PR状態を再検証する。Personal Access Tokenを画面、URL、ログ、送信データへ出力しない。

5. モックアップとの差異

本章はモックアップの再現仕様ではなく、本番実装で満たすべき仕様との差異を示す。外部設計としては「あるべき仕様」を優先する。

項目モックアップの振る舞い本設計で定義する振る舞い
候補データ固定のモックデータを使用する。認証利用者が参照可能な最新データをGitHub連携APIから取得する。
依頼送信依頼を作成せず、クエリパラメータ付きの一覧へ遷移する。サーバーへ依頼を登録し、登録成功後にのみ一覧へ遷移する。
送信失敗失敗状態を持たない。入力値を維持し、エラー内容と再試行手段を表示する。
二重送信ボタン無効化や冪等性制御を行わない。画面側の連続操作防止とサーバー側の冪等性制御を行う。
重複依頼登録済みPRも選択・送信できる。同一PR・同一最新コミットの有効な依頼を重複作成せず、既存依頼へ案内する。
Open PRが0件空のカード領域のみを表示する。選択可能なPRがないことを明示する。
選択値の再検証画面内の固定データだけを確認する。送信直前に権限、所有関係、PR状態をサーバー側で再検証する。
送信中状態定義しない。処理中表示と送信操作の無効化を行う。
キャンセル表示PR選択後にのみ表示する。モックの配置を踏襲し、PR選択後に表示する。共通シェルまたはパンくずからも一覧へ戻れる。
モックアップ確認時の注意モックアップは画面構成と操作感の確認用であり、実API接続、永続的な依頼作成、権限検証、送信エラー、重複制御は実装していない。
