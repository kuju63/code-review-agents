1. 画面デザイン

GitHub連携設定モックアップを開く

レビューエージェントが接続するGitHubのURLとPersonal Access Tokenを登録する。Classic PATとFine-grained PATの両方を受け付ける。

2. 画面項目の定義

共通ヘッダー、サイドナビゲーションおよびパンくずは共通画面項目に従う。

ID項目名種別必須初期値・表示内容備考
SET-01画面タイトル表示—GitHub連携設定設定目的を説明する。
SET-02保存完了通知通知—設定を保存しました。保存成功後に表示し、閉じる操作を提供する。
SET-03GitHub URLテキスト必須未設定時はhttps://github.comGitHub Enterprise Server利用時はインスタンスのルートURLを入力する。最大2,048文字。
SET-04Personal Access Tokenパスワード初回必須空欄。登録済みの場合はマスク済みプレースホルダー入力値は画面へ再表示しない。最大4,096文字。
SET-05保存ボタン—保存入力チェック成功時のみ保存する。処理中は無効化する。
PATの取り扱いPATは秘密情報として扱い、ログ、URL、画面ソース、ブラウザのlocalStorageまたはsessionStorageへ保存しない。保存先では暗号化または秘密情報管理機構を使用する。

3. 入力項目・操作項目の振る舞い

3.1 GitHub URLの入力チェック

IDチェック内容エラーメッセージ
SET-V01前後空白を除去した後、1文字以上かつ2,048文字以内であること。空欄:「GitHub URLを入力してください。」／超過:「GitHub URLは2,048文字以内で入力してください。」
SET-V02URLとして解析可能な絶対URLであり、スキームがhttpsであること。「HTTPS形式のGitHub URLを入力してください。」
SET-V03ホスト名が存在すること。ユーザー情報、クエリパラメータ、フラグメントを含まないこと。「GitHubインスタンスのルートURLを入力してください。」
SET-V04パスは空、/、またはGitHub Enterprise Serverがサブパス運用される場合の固定ベースパスであること。末尾の連続する/は保存時に除去する。「GitHubインスタンスのルートURLを入力してください。」

3.2 Personal Access Tokenの入力チェック

IDチェック内容エラーメッセージ
SET-V05初回登録時は必須。登録済みで空欄の場合は既存PATを変更しない。初回空欄:「Personal Access Tokenを入力してください。」
SET-V064,096文字以内であること。入力値の前後・途中に空白文字を含まないこと。入力値はトリミングせず、空白をエラーとして扱う。「Personal Access Tokenは空白を含めず4,096文字以内で入力してください。」
SET-V07Classic PATは大文字・小文字を区別してghp_で始まること。「Personal Access TokenはClassic（ghp_）またはFine-grained（github_pat_）形式で入力してください。」
SET-V08Fine-grained PATは大文字・小文字を区別してgithub_pat_で始まること。
SET-V09プレフィックスの後に空白以外の文字が1文字以上存在すること。判定条件は^(ghp_|github_pat_)\S+$とする。「Personal Access Tokenの値が不足しています。」
SET-V10PATの権限内容およびGitHubへの疎通による有効性検証は、この入力チェックでは行わない。—

3.3 操作

ID操作正常時の振る舞い異常時の振る舞い
SET-A01GitHub URLを入力する入力中は保存完了通知を非表示にする。保存時に正規化し、末尾の/を除去する。入力チェックエラーを項目直下に表示する。
SET-A02PATを入力する入力文字をマスク表示する。コピーや貼り付けは許可し、画面離脱または保存後に入力欄をクリアする。入力チェックエラーを項目直下に表示し、入力値をログへ出力しない。
SET-A03保存する全入力チェック後、GitHub URLとPATを安全な保存先へ一度だけ送信する。成功後はPAT入力欄を空にして保存完了通知を表示する。PATが登録済みで空欄ならURLのみ更新する。入力エラー時は保存せず最初のエラーへフォーカスする。通信・保存エラー時はPATを除く安全なメッセージを表示し、再試行を可能にする。
SET-A04保存完了通知を閉じる通知を非表示にする。保存済み設定は変更しない。非表示化できない場合も設定内容には影響しない。

4. 保存・表示仕様

  • 登録済みPATの値は取得APIから返却せず、画面上では登録済みであることだけをマスク済みプレースホルダーで示す。
  • PATを別の値へ更新する場合のみ新しいPATを入力する。空欄保存は削除を意味しない。
  • PAT削除が必要な場合は、空欄保存と混同しない独立した削除操作を将来設ける。本画面モックアップには含まれない。
  • 保存前のPAT権限検証は行わない。GitHub API利用時に認証・認可エラーが発生した場合は、その操作画面で再設定への導線を表示する。
