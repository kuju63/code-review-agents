3. 入力項目・操作項目の振る舞い

3.1 入力・状態チェック

ID対象チェック内容エラー時の表示・処理
RES-V01レビューIDURLクエリパラメータidを必須とし、対象レビューが存在して利用者に参照権限があることを確認する。「指定されたレビューは存在しないか、参照できません。」を表示し、SCR-01 コードレビュー一覧への導線を提示する。任意のレビューへ置換しない。
RES-V02ファイルID操作対象が表示中レビューの変更ファイルに含まれ、利用者に参照権限があることを確認する。最新のファイル一覧を再取得する。対象が存在しない場合は先頭の参照可能なファイルを選択し、変更を通知する。
RES-V03確認済み状態操作対象ファイルが存在し、要求値が確認済みまたは未確認のいずれかであることを確認する。最新状態を再取得し、保存前の画面状態へ戻して「ファイルの確認状態を更新できませんでした。」を表示する。
RES-V04コメントID操作対象が表示中レビューに含まれ、利用者に更新権限があることを確認する。「指定されたコメントは存在しないか、更新できません。」を表示し、最新のコメント一覧を再取得する。
RES-V05コメント状態遷移未対応から対応済みまたは誤検知へ、対応済みまたは誤検知から未対応へ遷移する操作であることを確認する。更新せず最新状態を再取得し、「コメントの状態が更新されています。内容を確認してください。」を表示する。
RES-V06再試行操作時点でもレビュー状態がエラーであり、同一レビューの再試行要求が処理中でないことを確認する。既に再試行済みまたは処理中の場合は最新状態を表示する。それ以外の不整合時は再試行を行わず理由を表示する。
RES-V07GitHub外部リンクSCR-04 GitHub連携設定のGitHub URLを基点として、Organization、リポジトリ、ブランチまたはコミットSHAからHTTPS URLを安全に生成できることを確認する。リンクを無効化し、「GitHubへのリンクを生成できません。」およびSCR-04への導線を表示する。

3.2 操作

ID操作前提条件正常時の振る舞い異常時の振る舞い
RES-A01コードレビュー一覧へ戻るなしパンくずの「コードレビュー一覧」を選択するとSCR-01へ遷移する。遷移できない場合は現在画面を維持する。
RES-A02再試行するレビュー状態がエラーボタンを無効化して再試行要求を一度だけ登録し、レビュー状態を「未実施」へ更新して通知を「再試行を受け付けました。」へ切り替える。解析が実際に開始された時点で「レビュー中」へ更新する。要求失敗時はエラー理由と再試行ボタンを維持する。既に処理中の場合は最新状態へ更新する。
RES-A03ファイル一覧を折りたたむ／展開する変更ファイルあり一覧の表示幅を切り替え、状態をブラウザ単位で保持する。折りたたみ時も選択ファイルの差分は維持する。状態を保存できない場合も当該表示中は切替を有効とする。
RES-A04ファイルを選択する対象ファイルを参照可能対象ファイルを強調し、差分ヘッダー、差分およびコメントを対象ファイルの内容へ切り替える。対象が削除済みまたは参照不可の場合は最新一覧を再取得し、RES-V02に従う。
RES-A05確認済みを切り替える対象ファイルを参照可能対象ファイルの確認状態を更新し、ファイル一覧と差分ヘッダーのチェック状態を同期する。コメント状態およびレビュー状態は変更しない。更新失敗時は元の状態へ戻し、エラーを表示する。
RES-A06対応済みにするコメントが未対応コメントを対応済みへ更新し、対応済みタグ、本文表示、コメント状態別件数およびレビュー状態を再表示する。更新失敗時は未対応のままとし、エラーを表示する。
RES-A07誤検知としてマークするコメントが未対応コメントを誤検知へ更新し、誤検知タグ、本文の取り消し線、コメント状態別件数およびレビュー状態を再表示する。更新失敗時は未対応のままとし、エラーを表示する。
RES-A08未対応に戻すコメントが対応済みまたは誤検知コメントを未対応へ更新し、状態タグ、本文表示、コメント状態別件数およびレビュー状態を再表示する。更新失敗時は元の状態を維持し、エラーを表示する。
RES-A09GitHubリンクを選択する安全なリンクを生成可能対象ブランチまたはコミットを新しいタブで開き、本画面を維持する。リンクを開かず、RES-V07に従ってエラーを表示する。

4. レビュー処理状態別表示

レビュー処理状態レビュー状態表示画面内容利用可能な操作
未開始（not_started）未実施解析未開始の通知を表示し、変更ファイル領域は表示しない。SCR-01へ戻る、画面再表示
解析中（analyzing）レビュー中スピナーと解析中の案内を表示し、変更ファイル領域は表示しない。SCR-01へ戻る、画面再表示
失敗（error）エラーエラー理由と再試行ボタンを表示する。再試行要求の受付後は未開始（not_started）へ遷移し、受付通知へ切り替える。再試行、SCR-01へ戻る
レビュー済み・未対応あり（reviewed）対応待ち変更ファイル、差分、コメントおよび未対応件数を表示する。ファイル選択、確認済み切替、コメント状態変更、GitHubリンク
レビュー済み・未対応なし（reviewed）状態タグなし変更ファイル、差分、コメントを表示する。全コメントが対応済みまたは誤検知の場合、対応待ちタグを表示しない。ファイル選択、確認済み切替、コメント再オープン、GitHubリンク
状態更新本画面はレビュー処理状態を自動更新しない。未実施、レビュー中または再試行受付後の最新状態は画面を再表示して取得する。

6. モックアップとの差異

本番実装時の優先事項静的モックアップでは、レビューIDの未指定または不正時に先頭のモックデータを表示し、確認済み状態およびコメント状態をブラウザのlocalStorageへ保存する。また、操作失敗や競合を模擬しない。本番実装では、RES-V01からRES-V07の検証、認可、競合制御、永続化およびエラー表示を実装し、本設計書の振る舞いを優先する。
